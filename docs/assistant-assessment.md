# Financial research assistant assessment v1

This optional offline tool assesses financial claims, evidence support and
omissions in a **closed structured response contract**. It does not grade
arbitrary prose or call a language model. Existing ML archive APIs and schemas
remain compatible.

The versioned `benchmarks/assistant-v1/public/cases.json` contains 13 synthetic
evidence cases. `evaluator/labels.json` holds separately specified answers,
numeric tolerances, required evidence pointers, failure acknowledgements and
financial rationales. Numeric expectations are literal annotations checked by
independent Decimal calculations in tests; they are not generated by the
production reasoner. These are repository regression annotations, not an
external independent human audit. Labels and control responses are public in
the repository, so this is not an unseen model holdout.

Cases cover fee-adjusted profit/loss, external-flow-neutral return, currency and
unknown-basis comparisons, conflicting sources, omitted failed/skipped/interrupted
attempts, no completed result, prespecified sample sufficiency, lookahead,
multiple testing, unverified instruction-like source text and synthetic/live
scope. Correct citation text alone cannot make a wrong financial value or
unsupported decision pass.

```bash
quant-assistant-eval export --cases benchmarks/assistant-v1/public/cases.json --output packet.json
quant-assistant-eval baseline --cases packet.json --output baseline.json
quant-assistant-eval score --cases packet.json --labels benchmarks/assistant-v1/evaluator/labels.json --submission baseline.json --output report
quant-assistant-eval self-test --suite benchmarks/assistant-v1 --output regression
```

`python -m quant_agent.assistant_assessment` is equivalent. The core scorer and
baseline use only the standard library; they can be installed with
`pip install --no-deps -e .` in a dedicated environment. Other quant-agent features
still require the normal locked dependencies.

Candidate packets use an explicit field allowlist: case ID, question, sample kind
and source evidence. Gold labels/rationales/control answers are never included.
The baseline CLI receives only the public packet, computes from evidence and
does not dispatch on case IDs; renaming cases and changing fees tests that property.
For an external candidate, provide only the packet, response schema instructions
and the relevant question; keep evaluator files outside its accessible filesystem
or tools. Export alone is an information packaging boundary, not an OS sandbox.
The public contract explicitly describes each response field's shape: `claims`
is an array of `{key, value, evidence}` objects, not a metric dictionary. Pass that
contract with every request and request a single JSON response with no code or
process traces. Do not execute provider-generated code or repair answers using
evaluator labels. A syntactically valid JSON response still requires scoring.
JSON pointers are relative to each source's `content`, so they do not include a
`/content` wrapper. The contract also explains decisions and caveat meanings as
general rules; these do not supply numeric answers or per-case expected responses.
`response_json_schema` supplies the single-response JSON shape and claim value
types (real JSON booleans, integer counts and decimal strings). It can be sent as
`response_format.json_schema.schema`; provider schema enforcement still needs
verification. Do not silently coerce a returned string such as `"false"` to a boolean.
The schema describes preferred output, not all scorer acceptance rules: counts
must use integer literals without decimal points or exponents. JSON Schema's
`integer` type accepts `1.0`, while the frozen scorer requires a parsed Python
`int`; validate that lexical/type boundary separately.

Submission format:

```json
{
  "schema": "quant.assistant-submission/v1",
  "public_sha256": "CANONICAL_PACKET_SHA256",
  "candidate": {"id": "candidate-name", "kind": "external_submission", "code_sha256": null},
  "responses": [{
    "case_id": "net-return",
    "decision": "report_only",
    "claims": [{"key": "net_return", "value": "0.018", "evidence": ["ledger#/starting_equity", "ledger#/gross_pnl", "ledger#/fees"]}],
    "acknowledged_failures": [],
    "caveats": ["synthetic_fixture"]
  }]
}
```

The example is structurally illustrative and intentionally incomplete for the
full benchmark: each case must include all requested claims (net P&L as well as
net return in this case), all unsuccessful attempt IDs, and exactly the
applicable caveats. Decisions are `report_only`, `needs_replay` or `abstain`.
Evidence references are source IDs plus JSON pointers, never external URLs or
unverified arbitrary file paths. Numeric values use decimal fractions for returns
and stated major currency units for P&L. Supported claim keys and caveat vocabulary
are documented in the public response contract; they do not supply per-case answers.

Scoring requires the exact public evidence hash, one response per case, correct
claim values within predeclared tolerances, exact supporting evidence references,
correct decision, complete failure history and applicable caveats. Unknown extra
claims or narrative fields cannot bypass scoring. Missing cases stay in the
denominator. Duplicates, non-finite JSON numbers and identity mismatches fail closed.
Output directories and submission exports are created exclusively, preserving
earlier evaluations.

`report.json` and `report.html` include dimension coverage, per-claim expected and
actual values, errors, rationales and exact evidence/labels/submission/scorer
identities. The HTML is escaped and has no external scripts.

Version 1 requires exact citation pointer sets from frozen annotations; it does
not evaluate equivalence between complete-record and field-level references.
Report those citation mismatches separately from incorrect claim values. Do not
rewrite candidate answers or loosen labels after a live run to improve its score.
`self-test.json` separates evaluator control classification from the label-blind deterministic
baseline score. Ten negative controls exercise wrong net return, right quote with
wrong decision, omitted failures, conflict denial, unsupported profit, wrong
citation, missing abstention, lookahead, naive cashflow return and caveat gaming.

Passing evaluator controls establishes that those injected mistakes are detected.
Passing the deterministic baseline describes only this finite offline reasoner
on public synthetic regression fixtures. **Online model quality is not measured.**
No paid model, market data, trading action or real-market effectiveness is involved.

The `offline assistant assessment` CI job runs the real export/baseline/score/
self-test CLIs and uploads readable reports. The regular full-suite CI continues
to check existing quant-agent behavior independently.
